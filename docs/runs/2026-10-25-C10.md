## Provisional decisions (taken, reversible)
- The spec layout names `plan-viewer.js`. The slice names `static/js/it-plan-view.js`. The file follows the slice. The element is `<plan-viewer>`, which is the name in the review spec.
- `PlansBridge` is mixed into `RealBridge`, and `routes/__init__.py` notes that `plans.py` belongs to C10. Neither file is in the slice scope. The route cannot import `services/plan_render.py` (surfaces reach core only through the bridge), so the mixin is the same hook the other C slices use.
- Page images are PNG at 150 dpi, cached under the machine state directory `plan-cache/<version>/<page>.png`. A file that matches the latest snapshot is cached by that version id. A file that is not a snapshot yet is cached by `current` and the bytes' hash.
- A change that has new text uses the ins token. A removal uses the del token. The box is the normalised bbox from the plan engine.
- 1.x pins and clouds are read from `store.sqlite3` in the project or in `.iterthink/`, joined to `content.attributes` `snapshot_relpath`. `plan_page_index` is 0-based, matching the existing annotation code. Nothing writes them.
