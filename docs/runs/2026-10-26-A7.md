## Provisional decisions (taken, reversible)
- An edit gives the edited paragraph a new change id (the id hashes
  before/after). So the edit route re-renders the whole proposal body
  (`HX-Retarget: #main`) rather than one fragment; accept and reject return
  the one fragment plus the out-of-band `#change-status` bar.
- When the last change is decided, the route re-renders the body with the
  same `versions-changed` / `proposals-changed` triggers as Accept.
- 409 for a stale candidate returns the refreshed fragment with
  `class="change outdated"`. If that change id no longer exists (it was
  edited meanwhile), the whole body comes back with a notice, also 409.
- A 409 for a stale baseline at the final decision shows the existing
  "no longer fits the current file" notice.
- `review/detail.html` gets the same `htmx-config` meta as `home/index.html`
  so HTMX swaps 4xx responses (otherwise the 409 fragment is dropped).
- Real-bridge logic lives in `services/change_verdicts.py`; `accept` now goes
  through the shared `accept_files`, which keeps `bridge_real.py` at 339 lines.

## Proposed changes to rules, decisions, other slices
- A5 `review-keys.js`: `a` / `r` / `e` act on the whole proposal. With
  per-change fragments they could act on the active `.change`
  (`.change.active form[action$="/accept"]`). A5 owns the file.
- A small per-slice stylesheet (`css/a7-review.css`) for `.change-actions`
  and `.change.outdated` would help; the scope list did not include CSS, so
  the fragments use unstyled forms for now.
- `bridge_fake.py` (human-owned) was already 752 lines before this slice and
  is 827 now. Splitting it into mixins like the real bridge would bring it
  under the 400-line rule.
