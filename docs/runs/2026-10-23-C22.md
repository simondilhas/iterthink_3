## Provisional decisions (taken, reversible)
- The claim file stores `since` as well as machine, user and heartbeat. `since` is how release tells our claim from a later one.
- `holder` treats a claim as stale when the heartbeat is 2 minutes old or older.
- `acquire` never replaces a claim, including a stale one. `take_over` is the only way.
- `take_over` of a live claim raises `Claimed`. `take_over` with no claim raises `ValueError`.
- The caller owns the heartbeat thread. `HEARTBEAT_EVERY` is 30 seconds. This module only rewrites the file when `heartbeat()` is called.
- The banner partial is `web/templates/partials/claim_banner.html`. No page includes it yet. Chats, tasks and apps are later slices.
- A project without an id in `project.yaml` logs the takeover under the folder name.

## Proposed changes to rules, decisions, other slices
- B1's slice text says every other open proposal on the same paths gets a conflict event as soon as one is accepted. The contract invariant accepts a second proposal when the file bytes still match the baseline it was made from, and it rejects a proposal that was already marked. `_compete` now writes that event only when the accept made the other proposal's baseline bytes stale. `reject` still succeeds when the status is already `conflict`, so a person can turn a competing proposal down. `accept` of a conflict proposal still raises `Conflict`.
