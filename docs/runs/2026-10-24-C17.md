## Provisional decisions (taken, reversible)
- The store that is read is `<store>/store.sqlite3` plus the snapshot files beside it. The spec says "store_db". In this tree `persistence/store_db.py` is the embedding index, which has no versions. Content, projects, verdicts and annotations live in `store.sqlite3`. The RAG file is not read.
- There is no author column. The snapshot author is `display_label`, then `snapshot_reason`, then `import`. The description is `{author} {original_ts} {path}`. The version event actor is `user:{author}`.
- Verdict events have no `proposal` key, so they are not treated as a verdict on a 2.0 proposal. Payload: `imported_from`, `original_ts`, `path`, `verdict`. Annotations use type `annotation` with `body`, `imported_from` and `original_ts`.
- Each snapshot is the whole tracked tree with that version's bytes overlaid. Snapshotting only the one file would drop the other project files from the head.
- The sqlite file is opened `mode=ro&immutable=1`. A plain read-only open of a WAL database created a sidecar and changed the store digest.
- The page is `GET/POST /import`. Routes cannot import `services.importer_1x`, so `RealBridge.import_preview` and `import_run` are the only way in. `FakeBridge` has neither, and the page says import is not available.
- `compete()` moved from `bridge_real.py` into `proposals.py` with the same behaviour, so the bridge file could take the two import methods and stay at 399 lines.
- A second run calls `make_project` and then stops when an `import` event already names this store. The disk file has to already match the last imported body, or the disk scan on that second open writes a new version.
