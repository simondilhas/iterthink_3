## Blocked — needs your answer
1. **Question:** The contract `TaskStatus` is `todo|running|review|done|failed`, and the bridge only has `task_create`, `task_start` and `tasks`. The spec has eight statuses (`backlog|ready|running|needs-input|review|done|rejected|cancelled`) and methods for claim, update, ask, answer, complete and cancel. Should the contract grow to the spec, or should the board keep mapping onto the five statuses?
   **Why it matters:** The board, the task file and MCP already use the spec words. `TaskInfo.status` still returns the five contract values, and the extra methods live on the mixin. The slice stays `in-progress` until the contract catches up, so it is not merged.
   **Options:** A) Add the eight statuses and the missing methods to `bridge.py`, `bridge_fake.py` and `tests/v2/contract/`. B) Keep the five statuses and three methods forever, and treat the mixin as the real API. **I'd pick:** A, because the spec and the board already use those words, and the mapping (backlog/ready → todo, needs-input/rejected/cancelled → failed) hides a real state from every surface that only sees `TaskInfo`.
