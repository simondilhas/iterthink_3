## Provisional decisions (taken, reversible)
- The banner is included from the project overview (`project/page.html`, `routes/projects.py`). Those two files were not in the original scope list. The acceptance test opens that page, and nothing else renders it.
- The break the banner test uses is a checkpoint whose other-machine head is no longer in that log. Both chains still verify, so the project page can list files, and this machine can append the audit event. `append` refuses a log that does not verify, so a hash break in this machine's own log cannot receive a new audit line. The banner text is still produced by `verify_project`. The page's file list calls `read_all`, which raises before the template in that case.
- Outside the test runner, opening a folder starts the check on a daemon thread named `iterthink-audit`. The project page runs the check itself so the banner is in the response. Under pytest the check finishes before open returns.
- The handover event's actor is `user:local`. The bridge method takes no actor.
- The event records mode, the head hash and sequence of every log that still verifies, and the latest snapshot id. It does not record the destination path.
- A client bundle copies source files and `.iterthink/exports/`, then adds `verification/` (heads, snapshot id, verdict CSV, the logs under `verification/.iterthink/log/`, and `verify_log.py`). Chats, apps, prompts, transcripts, versions, blobs and the original log directory are not copied. Rejected proposal bytes stay in the versions store and do not travel. Verdict rows do travel, in the CSV and in the logs.
- Full handover writes `.iterthink/exports/audit-<date>/` after the handover event, then copies the folder. The report says the record is tamper-evident.
- Symlinks are copied as links on a full handover and skipped on a client handover.
