## Provisional decisions (taken, reversible)
- One scrolling page with a left list of anchors (like VS Code settings), not one
  fragment per section. Ollama status loads after the page (`settings/models.html`).
- Inside a project, a "Change for: this project / workspace" switch picks the level
  for inherited values; machine values (models, keys, paths, appearance) are always
  per machine (`settings/window.html`, `routes/settings_window.py`).
- Settings files (prompts, checks, impact checks, rules, agents) are edited as raw
  YAML at a fixed level per scope: workspace from the start screen, project inside
  a project. A file not yet edited shows the seed text (`settings_window.py`).
- Privacy shield categories are shown read-only; token totals per period are not
  shown yet (only the period setting).
- Writing a machine value rewrites the user `config.yaml` with `yaml.safe_dump`, so
  comments in that file are dropped (`app_settings.py`).
- A machine value that equals the seed counts as "default", so a copied seed file
  does not mark every row as changed (`app_settings.value`).
- `shortcut_keys` reads values with `settings.get`, not `all_settings`, because it
  runs on every page and `all_settings` refreshes the storage trend baseline.
- The Ollama probe (`installed_models`) lives in `ai/local_model.py`; the boundary
  test keeps remote clients inside `ai/` and `egress`.
- Escape no longer clears the side panes on the Settings page (the left pane holds
  the section list there).

## Proposed changes to rules, decisions, other slices
- Spec, "The line (three-dot menu)": add "Settings" to the start-screen menu and
  note that project pages carry the same three-dot menu (Settings, Open project,
  Open folder, Start screen).
- `defaults/config.yaml`: comments that explain keys are lost once a user saves
  from the Settings page. A comment-preserving writer would need a new dependency
  (ruamel.yaml); deciding that is yours.
