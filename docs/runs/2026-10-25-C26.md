   **Options:** A) Add `image` to `FileDiff.kind` and the contract tests, then the engine returns it. B) Keep `binary` plus `details["regions"]`, which is what this slice ships. **I'd pick:** A, because the spec names the kind. B is what runs until that contract edit.

## Provisional decisions (taken, reversible)
- Regions are `[x, y, width, height]` from 0 to 1, so the boxes can use CSS left/top/width/height. Plan boxes stay `[x0, y0, x1, y1]`. Threshold is `THRESHOLD = 24` in `engine_image.py` (max channel absolute difference). Changed pixels are grouped with a 4-connected fill. The earlier image is resized to the later image before the compare. (`iterthink/compare/engine_image.py`)
- The review route cannot read snapshot bytes itself. The engine puts the original bytes in `details["before_png"]` and `details["after_png"]` as base64, and the partial uses data URLs. The key name stays `before_png` for jpeg and webp too. The media type comes from the suffix. A large photo becomes a large page. (`history.py` `_image_view`)
- `history.py` and `templates/history/diff.html` belong to A5. They were edited so a diff whose `details["regions"]` is a list includes `partials/diff_image.html`. Same pattern as the model partial. Decode failures omit `regions` and stay on the generic diff.
- The range sits under the picture. The later image is clipped by the range and does not receive pointer events, so a drag reaches the control. Region boxes are inside that clip, positioned with `cqw` against the stage.
