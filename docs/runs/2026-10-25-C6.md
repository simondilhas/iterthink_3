## Blocked — needs your answer
1. **Question:** `AppInfo.url` is the contract field. The spec delivers the app by `srcdoc` on the shell origin. This slice sets `url` to `None`. The page is `/p/{id}/apps/{slug}`.
   **Why it matters:** a caller that opens `AppInfo.url` gets nothing.
   **Options:** A) Keep `url` empty and use the page (this run). B) Add a srcdoc field to `AppInfo` in the human-owned contract. **I'd pick:** A, because the contract cannot grow a field from this slice and the spec forbids a second origin.
2. **Question:** The line still says "coming soon" for an app. `tests/v2/services/test_intent.py` requires `soon=1` for "Door schedule from the model", and `tests/v2/web/test_c3_line.py` requires the words "coming soon". Those files belong to C3.
   **Why it matters:** the spec's line example opens an app. This slice builds apps from the Apps page only.
   **Options:** A) Update those two assertions now that C6 exists. B) Leave the line on "coming soon" (this run). **I'd pick:** A.
3. **Question:** Vendor scripts for a frame. `web/app.py` has no Content-Security-Policy header, and `PUBLIC_PREFIXES` is only `/static/`. `GET /app-vendor/{name}` sends `Access-Control-Allow-Origin: null` but still requires the token. The frame bridge is inlined, so the shipped examples do not fetch vendor files.
   **Why it matters:** a sandboxed frame cannot load `/static/vendor/` until that prefix is public and allows the opaque origin.
   **Options:** A) Add `/app-vendor/` to `PUBLIC_PREFIXES` and the same ACAO header on `/static/vendor/`. B) Keep the token gate (this run). **I'd pick:** A.
4. **Question:** The spec's headless dry run needs a browser this project does not ship. This slice does the static checks and a dry-run call of every non-propose bridge name.
   **Why it matters:** a script error that only appears in a browser is not caught before the app is shown.
   **Options:** A) Stay with the static plus dry-run calls (this run). B) Add a headless browser later. **I'd pick:** A until a browser is a dependency.
5. **Question:** Kept-app matching. The slice asks for local embeddings. An ONNX model would be a new dependency and a download.
   **Why it matters:** the builder sees up to three kept purposes. The match is word overlap, not embeddings.
   **Options:** A) Words longer than two characters, up to three purposes (this run, `iterthink/services/app_context.py`). B) Add an embeddings model later. **I'd pick:** A.
